# Features without UI controls

Reviewed the HTTP routes, realtime command schemas, shared models, server implementations, and their client callers on 2026-09-17. The meeting-room setting is implemented in this change. The findings below describe the remaining gaps; most require a write API as well as a control.

| Capability | Existing behavior | Missing control and implementation |
| --- | --- | --- |
| Scheduled meeting management | Saved meetings have a title, time, duration, room, and status. Meetings can be started and joined. | Create, reschedule, cancel, or end a scheduled meeting. No scheduling write API exists. See [meeting model](../packages/shared/src/index.ts), [meeting commands](../apps/server/src/meetings/meeting-protocol.ts), and [Meetings panel](../apps/client/src/components/MeetingsPanel.tsx). |
| Floors and office details | Multiple floors, levels, names, sizes, backgrounds, and office identifiers are stored. The UI can view floors and move the start point. | Add/remove floors or edit their details and office/team names. No corresponding write API exists. [Models](../packages/shared/src/index.ts), [initial workspace](../apps/server/src/initial-data.ts), [floor picker](../apps/client/src/components/TopBar.tsx). |
| Portal destinations | Portal travel resolves a destination floor from the object's label. | Configure a destination when placing or editing a portal. The build command cannot set labels. [Portal resolution](../packages/shared/src/floor-portals.ts), [build commands](../apps/server/src/protocol.ts), [Build panel](../apps/client/src/components/BuildPanel.tsx). |
| Object names | Placed objects can have a label, used for boards and world interactions. | Rename a placed object. Moving and rotating preserve its label, but no editing command accepts a new one. [Object model](../packages/shared/src/assets.ts), [Build panel](../apps/client/src/components/BuildPanel.tsx). |
| Room capacity | Capacity is saved, otherwise calculated when a room is detected, and enforced on meeting entry. | Set a room's capacity. `RoomSettings` and its editor do not include it. [Room models](../packages/shared/src/building.ts), [room detection](../packages/shared/src/room-detection.ts), [meeting entry](../apps/server/src/world/world-runtime.ts). |
| Room chat channels | The conversation model and Messages panel support room channels. Direct-message creation has a working UI. | Create or rename room channels. Building a room does not create a room chat. [Store](../apps/server/src/store.ts), [Messages panel](../apps/client/src/components/ChatPanel.tsx). |
| Member profile editing | Display names, emails, and job titles are stored and displayed; avatar, availability, roles, and build permissions have controls. | Edit profile names or job titles after account creation. No profile-edit write API exists. [Member model](../packages/shared/src/index.ts), [People panel](../apps/client/src/components/PeoplePanel.tsx), [member routes](../apps/server/src/app.ts). |
| Member removal | `WorkspaceStore.removeMember` performs workspace cleanup. | Remove an existing member through an authenticated workflow. No removal route or People action exists; auth/session and connected-player cleanup would also need wiring. [Store](../apps/server/src/store.ts), [People panel](../apps/client/src/components/PeoplePanel.tsx). |
| Window lighting | Windows store light color, intensity, and depth; rendering uses them. New windows use fixed defaults. | Edit these properties. The build editor only places, moves, and removes windows. [Window model](../packages/shared/src/building.ts), [window placement](../apps/server/src/world/layout-plan.ts), [Build panel](../apps/client/src/components/BuildPanel.tsx). |

The realtime command scan found client references for all implemented action families. The two direct settings commands without callers (`room.update_settings` and `game.settings_update`) have equivalent UI operations through the room-settings proposal flow, so they are not additional missing features.

Meeting invitations and locking, camera/microphone selection, screen sharing, organisation changes, room access/build rules and previews, funds/votes, personal inventory, game settings, whiteboards/checklists, Spotify, and GitHub already have UI entry points. Integration credentials, email delivery, database settings, and WebRTC relay settings are deployment configuration.

This is a source audit of implemented capabilities, not a completeness claim against the product specification. Browser verification for this change covers the meeting-room flow; the other findings were traced in source.
